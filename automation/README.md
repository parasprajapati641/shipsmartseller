# Meesho Shipping Charge Automation

Production-grade Playwright + TypeScript automation for comparing Meesho shipping charges across optimized image variants generated by Ship Smart Seller.

## Overview

This module:

1. Logs into the Meesho Seller portal **once** and persists the session
2. For each image variant: uploads → waits for shipping calculation → reads charge → saves screenshot → removes image
3. Returns the variant with the **lowest shipping charge**

Designed to be modular — callable from CLI now, exposable as an API for the React app later.

## Prerequisites

- Node.js 18+
- Meesho Seller account credentials
- Playwright browsers (installed once)

```bash
npm install
npx playwright install chromium
```

## Environment Variables

| Variable                 | Required            | Description                                                            |
| ------------------------ | ------------------- | ---------------------------------------------------------------------- |
| `MEESHO_SELLER_EMAIL`    | For automated login | Seller account email or mobile                                         |
| `MEESHO_SELLER_PASSWORD` | For automated login | Seller account password                                                |
| `MEESHO_HEADED`          | No                  | Set to `1` to show browser window (needed for OTP / interactive login) |
| `MEESHO_LOG_LEVEL`       | No                  | `debug`, `info`, `warn`, or `error` (default: `info`)                  |

If credentials are not set, the login flow falls back to **interactive mode** — a browser window opens and you complete login manually.

## Quick Start

### 1. Login (one-time, session reused)

```bash
# With env credentials (headless)
MEESHO_SELLER_EMAIL=you@example.com MEESHO_SELLER_PASSWORD=secret npm run automation:login

# Interactive / OTP (headed)
MEESHO_HEADED=1 npm run automation:login
```

Session is saved to `automation/.session/meesho-session.json`.

### 2. Run shipping comparison

Generate variants in the Ship Smart dashboard (download all sizes), then:

```bash
npm run automation:compare -- --images ./path/to/variants
```

Or directly:

```bash
npx tsx automation/cli.ts compare --images ./path/to/variants
```

### 3. Programmatic usage

```typescript
import { runShippingComparison } from "./automation/index.js";

const result = await runShippingComparison([
  { name: "5kb", path: "./variants/product_5kb.jpg" },
  { name: "10kb", path: "./variants/product_10kb.jpg" },
  { name: "15kb", path: "./variants/product_15kb.jpg" },
]);

if (result.best) {
  console.log(`Best: ${result.best.variantName} — ₹${result.best.shippingCharge}`);
}
```

## Variant Naming Convention

Matches the dashboard download format from `src/routes/_authenticated/dashboard.tsx`:

```
{original_filename}_{targetKB}kb.jpg
```

Example: `dress_photo_10kb.jpg`, `dress_photo_25kb.jpg`

The dashboard generates variants at target sizes: **5, 10, 15, 20, 25, 30, 40, 50 KB**.

## Architecture

```
automation/
  config/
    selectors.ts       # Meesho UI selectors (update when UI changes)
    constants.ts       # URLs, timeouts, paths
  lib/
    logger.ts          # Structured logging
    retry.ts           # Exponential backoff retry
    errors.ts          # Typed error hierarchy
    selectors.ts       # Selector → Playwright locator resolver
  session.ts           # Playwright storageState persistence
  login.ts             # One-time login, session reuse
  upload.ts            # Image upload + removal
  shipping.ts          # Wait for shipping calculation
  parser.ts            # ₹ amount extraction from page text
  runner.ts            # Orchestrates full comparison flow
  cli.ts               # CLI entry point
  index.ts             # Public API exports
  types.ts             # Shared TypeScript types
```

## Selector Verification (IMPORTANT)

All selectors in `config/selectors.ts` are **placeholders** based on common Meesho supplier portal patterns. Before production use:

1. Log into https://supplier.meesho.com/ with your seller account
2. Navigate to the product creation page
3. Open Chrome DevTools → inspect elements for:
   - Login form inputs
   - Image upload file input / drop zone
   - Shipping charge display area
   - Remove image button
4. Update `automation/config/selectors.ts` with verified selectors
5. Prefer stable attributes: `data-testid`, `aria-label`, `role`
6. Re-run `npm run automation:login` and a test comparison

### URLs to verify

| Constant                      | Current Value                               | Action                 |
| ----------------------------- | ------------------------------------------- | ---------------------- |
| `MEESHO_URLS.login`           | `https://supplier.meesho.com/`              | Verify login URL       |
| `MEESHO_URLS.productCreation` | `https://supplier.meesho.com/panel/v3/new/` | Verify add-product URL |
| `MEESHO_URLS.dashboard`       | `https://supplier.meesho.com/panel/v3/home` | Verify dashboard URL   |

Update `automation/config/constants.ts` if Meesho has changed these paths.

## Error Handling

- **Retry**: Transient network/navigation failures retry up to 3 times with exponential backoff
- **Screenshots**: Captured on failure to `automation/.screenshots/`
- **Typed errors**: `LoginError`, `UploadError`, `ShippingCalculationError`, `ParseError`, etc.
- **Browser cleanup**: Always closed in `finally` block

## Troubleshooting

| Issue                      | Solution                                                        |
| -------------------------- | --------------------------------------------------------------- |
| Session expired            | Run `npm run automation:login` again                            |
| OTP required               | Set `MEESHO_HEADED=1` and complete OTP in browser               |
| Selectors not found        | Update `config/selectors.ts` after inspecting live Meesho UI    |
| Shipping charge not parsed | Check screenshot in `.screenshots/`, update parser or selectors |
| Browser not installed      | Run `npx playwright install chromium`                           |
